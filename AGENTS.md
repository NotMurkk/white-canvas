## TD Map Maker

This app hosts the TD Map Maker: a Mario Maker-style map editor for a 2D top-down tower defense game, plus a reference player. See README.md for the full picture.

- `/` is the map editor (`apps/map-editor`, React + Phaser). It is loaded in the browser only (`src/routes/index.tsx`): Phaser needs a real DOM and WebGL, so never import it from server code or render it during SSR.
- `/play?map=/maps/<id>.map.json&theme=<id>` plays a saved map (`apps/game`).
- `packages/*` hold the shared map format, rules, pathing, simulation and renderer. The game runs the same code, so keep gameplay logic there, not in React components.
- `maps/`, `themes/`, `content/` and `assets/atlases/` are data. They are served at those paths in dev and copied into production builds by `tools/vite-repo-files.ts`.
- Every map in `maps/` must pass the clear check; `npm test` fails otherwise. Save maps from the editor or run `npm run clearcheck`, never hand-edit the stamp.
- `assets/atlases/*` are generated by `npm run art` from downloaded tile packs that are not in the repo. Don't edit them by hand.
- The editor has its own stylesheet (`apps/map-editor/src/styles.css`), scoped to `.app`, and doesn't use Tailwind or shadcn. Keep it that way.
- Before committing: `npm test` and `npm run typecheck` (two configs: Lovable's `tsconfig.json` for `src/`, `tsconfig.tdmm.json` for the editor, packages and tools).
- Hosted saving goes to GitHub as pull requests (`src/lib/github-maps.server.ts`, called through `src/lib/maps.functions.ts`). It needs the `GITHUB_TOKEN` and `EDITOR_KEY` secrets. Keep the token server-side: never read it in client code or put it in a `VITE_` variable.
- `.github/workflows/check.yml` runs the tests on every pull request; keep it passing.
